Statement of Work
Scope, objectives, deliverables, and constraints

The customer requires an Autonomous Multi-Agent Software Factory — an AI-orchestrated delivery platform that accepts structured project inputs and coordinates a sequential pipeline of specialist AI agents to produce production-ready, deployable software. This is a pipeline-level automation system, not a copilot or code-assist tool. Once a requirement is submitted, the system self-directs through all phases of software delivery with minimal human intervention.

🎯 Business Objectives
  • Reduce feature delivery time by up to 80% vs traditional Agile execution
  • Maintain enterprise coding standards and governance automatically
  • Provide real-time sprint telemetry and live agent status dashboard
  • Produce audit-ready documentation and full traceability matrix
  • Enable production readiness validation before any PR merge
📦 Deliverables
  • FastAPI backend orchestrator with 10 specialist AI agents
  • Angular 17 real-time dashboard with SSE-based live updates
  • Docker-containerised deployment pipeline for Azure
  • Azure DevOps CI/CD pipeline with 4-stage workflow
  • Automated test suite (unit + integration + E2E + security)
  • GitHub PR automation with generated metadata and checklist
✅ In Scope
  • Multi-agent orchestration platform (FastAPI backend + Angular frontend)
  • Requirement parsing from PDF / DOCX / Markdown / URL input
  • Figma mockup analysis via URL + Figma REST API
  • Code generation for Angular 17 frontend and Python FastAPI backend
  • Auto-generated unit, integration, and E2E tests (Pytest + Playwright)
  • Security compliance scan (Bandit + OWASP LLM review)

  • Azure DevOps pipeline integration and sprint board sync
  • OpenTelemetry observability with Azure Application Insights
  • MongoDB + Redis state management and event bus

Database Strategy

🍃 MongoDB (Primary Store) — Recommended

MongoDB is the primary persistence layer for all workflow state, agent outputs, sprint plans, user stories, and generated file metadata. Its document model is ideal because agent outputs are dynamic, nested, and schema-evolving — structured relational tables would require constant migration as agents improve.

  • Why not PostgreSQL? Agent outputs are deeply nested JSON with variable structure — forcing this into relational tables would create constant schema churn
  • Why not DynamoDB? Complex queries (workflow status aggregation, sprint analytics) need MongoDB's aggregation pipeline
  • Motor (async driver) for Python async/await compatibility with FastAPI
  • Version: MongoDB 7.0 Community or Atlas M10+
⚡ Redis (Event Bus + Cache) — Essential

Redis handles real-time SSE event distribution, task queue management, rate limiting counters, and circuit breaker state. It replaces the in-memory asyncio.Queue approach, enabling multi-instance horizontal scaling of the backend.

  • SSE pub/sub: Redis Pub/Sub distributes events to all backend replicas
  • Task queue: Redis List as FIFO queue (LPUSH / BRPOP) for workflow tasks
  • Rate limiting: Redis INCR + EXPIRE for sliding window rate limits
  • Circuit breaker state: Redis Hash per LLM provider with TTL
  • Version: Redis 7.0+ / Azure Cache for Redis (C1 tier minimum)

# config/database.py — Motor async MongoDB client setup
from motor.motor_asyncio import AsyncIOMotorClient
from redis.asyncio import Redis
from .settings import settings

class DatabaseManager:
    mongo_client: AsyncIOMotorClient = None
    redis_client: Redis = None

    async def connect(self):
        # MongoDB
        self.mongo_client = AsyncIOMotorClient(
            settings.MONGODB_URI,
            maxPoolSize=10,
            minPoolSize=2,
            serverSelectionTimeoutMS=5000
        )
        self.db = self.mongo_client["agent_factory"]
        await self.mongo_client.admin.command('ping')
        print("✓ MongoDB connected")

        # Redis
        self.redis_client = Redis.from_url(
            settings.REDIS_URL,
            encoding="utf-8",
            decode_responses=True,
            max_connections=20
        )
        await self.redis_client.ping()
        print("✓ Redis connected")

    async def disconnect(self):
        if self.mongo_client:
            self.mongo_client.close()
        if self.redis_client:
            await self.redis_client.aclose()

    def get_collection(self, name: str):
        return self.db[name]

db_manager = DatabaseManager()

🧠 Anthropic Claude API  Primary AI Engine  Required

Why This API

Claude is the primary reasoning engine for all 10 agents. Its 200K token context window handles large requirement documents. import httpx, re

async def fetch_figma_design(figma_url: str) -> dict:
    match = re.search(
        r'figma\.com/file/([^/]+).*node-id=([^&]+)',
        figma_url

            params={"ids": node_id},
            headers={"X-Figma-Token": settings.FIGMA_TOKEN}

class ADOClient:

        creds = base64.b64encode(f":".join(["", token]).encode()).decode()
        self.headers = {
            "Authorization": f"Basic {creds}",
            "Content-Type": "application/json-patch+json"

                f"{self.base}/wit/workitems/$User Story?api-version=7.0",

  • API Cost Liability. Each workflow run consumes Anthropic and OpenAI API tokens. Complex requirements may consume $2–$5 per workflow. Set hard spend limits in your API provider dashboard before exposing this system to external users or automated triggers.
  • No Correctness Guarantee. LLMs can generate code that appears syntactically correct but contains logical errors. The auto-generated test suite does not guarantee functional correctness for your specific business requirements.
  • Data Privacy. Requirement documents and code are sent to Anthropic's and OpenAI's APIs. Do NOT submit requirements containing PII, trade secrets, or data covered by HIPAA / PCI-DSS / GDPR without evaluating the respective data processing agreements.
  • GitHub Token Scope. Use a fine-grained Personal Access Token scoped to the target repository only with contents:write and pull_requests:write permissions. Never use an org-wide token.
  • Rate Limits Under Load. Anthropic imposes per-minute token limits. Under heavy concurrent use, workflows may queue or slow. The MAX_CONCURRENT_WORKFLOWS setting (default 5) exists specifically to prevent rate limit breaches.
  • Generated Code Ownership. Review your Anthropic and OpenAI terms of service regarding intellectual property of AI-generated output before deploying generated code in commercial products.
⚠️ Known Limitations
  • Context window limits restrict very large requirement documents (> 50 pages PDF)
  • Code generation targets Angular 17 + Python FastAPI only — no React, Vue, Node.js backend
  • No support for monorepo structures with complex inter-package dependencies
  • Figma to code quality depends heavily on design file naming conventions
  • Concurrent workflow cap of 5 is LLM rate-limit driven — not configurable without risk
  • PR Agent cannot handle merge conflicts in existing files
  • Generated tests require manual validation of correctness — they test structure, not business logic
  • No incremental updates — each run creates a new feature branch, not modifying existing code
🗺️ Recommended Roadmap
  • Multi-stack support: React + Node.js, Vue + NestJS generator agents
  • Human-in-the-loop approval between Architecture Agent and code generation
  • Fine-tuned model on your organisation's codebase for higher quality and standards adherence
  • Incremental workflow: update existing features (not just greenfield generation)
  • Multi-tenant isolation with per-org API key management and usage budgets
  • Slack / Teams integration for workflow status notifications
  • Pre-flight cost estimate before submitting workflow (token count prediction)
  • Agent memory: RAG over past workflows for improved consistency across sprints
